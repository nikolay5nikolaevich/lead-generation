# Этап 7 — Гейты качества: валидация фактов и проверка письма

Разделы `SPEC.md`: 5.4, 5.7, 10.

## Задача

Промпт снижает вероятность выдумки, но не исключает её. Этот этап добавляет
проверки кодом: непроверенный факт не попадает ни в CSV, ни в письмо.

## Что сделать

- `leadgen/graph/nodes/validate.py` — узел `validate_facts`: берёт текст страницы
  из кэша, нормализует (пробелы включая неразрывные, регистр, типографские кавычки),
  проверяет вхождение каждого `quote`. Непрошедшие факты выбрасывает и пишет в лог,
  что именно отброшено. Ложное срабатывание (факт есть, но записан иначе) —
  допустимая цена: пропустить выдумку хуже.
- `leadgen/graph/nodes/verify_draft.py` — узел `verify_draft`: вторым вызовом модели
  извлекает из письма утверждения и сверяет каждое с фактами в состоянии.
  Есть непокрытые утверждения — письмо переписывается один раз, при повторной
  неудаче статус `DRAFT_UNVERIFIED`.
- Правка `company.py`: вставить оба узла в подграф по топологии из раздела 4
  спецификации. Остальную сборку не трогать.
- Колонка CSV «сколько фактов отброшено валидатором».
- `tests/test_validate.py` — факт с выдуманной цитатой отбрасывается, факт
  с другим форматированием пробелов и кавычек проходит.

## Приёмка

`pytest -q` и `leadgen run --limit 5`: тесты проходят; в логе видно число отброшенных
фактов; в CSV нет ни одного письма со статусом `READY`, содержащего утверждение
без соответствующего факта. Вручную подставленное в письмо выдуманное утверждение
ловится `verify_draft`.
