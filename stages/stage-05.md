# Этап 5 — Реальный LLM: structured output, факты, скоринг, письмо

Разделы `SPEC.md`: 3, 5.1, 5.3, 5.5, 5.7, 6.

## Задача

Заменить `FakeLLM` реальной моделью по подписке Claude Pro через `claude -p`.
После этого этапа проект работает целиком на реальных данных.

С этого этапа каждый реальный прогон расходует лимит подписки. Лимит сбрасывается
по времени, а не пополняется деньгами. Прогоны начинай с `--limit 2`.

## Перед началом

- `claude -p "ответь одним словом: ok"` отвечает — CLI залогинен в подписку.
  Не отвечает — скажи, как залогиниться (`claude` → `/login`), и остановись.
- В окружении нет `ANTHROPIC_API_KEY`: если он задан, CLI пойдёт через платный API.

## Что сделать

- `leadgen/llm/client.py` — вызов модели через `claude -p` (`subprocess`). Принимает
  промпт и Pydantic-модель ответа, передаёт схему через `--json-schema`
  (`model_json_schema()`), проверяет ответ через `model_validate_json()`, сначала
  смотрит в кэш. Каждый реальный вызов увеличивает `llm_calls` в `Budget`.
- `leadgen/storage/llm_cache.py` — SQLite-таблица `hash(промпт + схема) → ответ`.
- `leadgen/llm/prompts.py` — промпты для четырёх задач: запросы из ICP, извлечение
  фактов, скоринг по рубрике, черновик письма. Промпт фактов требует дословную цитату
  и разрешает не отвечать, если факта на странице нет.
- Реальный класс LLM с тем же набором методов, что у `FakeLLM`; переключение
  по `--offline` — как у провайдеров на этапе 4.
- Правка узлов `search.py` (`plan_queries`), `facts.py`, `score.py`, `draft.py`.
- Итоговый балл 0–100 считает Python взвешенной суммой (уже так в `score.py`),
  модель ставит по каждому критерию только 0–3 с обоснованием.
- Ввод ICP в CLI: текст из файла (`--icp <путь>`), передаётся в `icp_text`.
- LangSmith: переменные в `.env.example`, трасса прогона видна в интерфейсе.
- Число вызовов модели за прогон печатается в конце лога.

Промпты на этом этапе — первая разумная версия. Доводить их до качества имеет смысл
на этапе 8, когда появится eval и результат станет числом.

## Приёмка

`leadgen run --limit 5 --icp <файл ICP>`: в CSV пять строк с настоящими фактами,
баллами с обоснованием по каждому критерию и черновиками писем. Число вызовов модели
напечатано в конце лога и записано в `PROGRESS.md`.

Повторный запуск той же команды: вызовов модели нет, ответы берутся из кэша.
`leadgen run --offline --limit 3` и `pytest -q` по-прежнему проходят.
