# Этап 4 — Реальные источники данных: поиск, фетчер, email, кэш

Разделы `SPEC.md`: 5.1, 5.2, 5.6, 6.

## Задача

Заменить фейковые поиск, загрузку страниц и поиск email на реальные реализации
за теми же интерфейсами из `leadgen/providers/base.py`. Код графа не меняется:
меняется только то, что подставлено под интерфейс.

LLM на этом этапе остаётся фейковым (`FakeLLM`): одна новая внешняя зависимость
за раз. Поисковые запросы пока берутся из `fixtures/llm_answers.json` (`queries`) —
подставь туда запросы под реальный ICP владельца.

## Перед началом

- В `.env` есть `TAVILY_API_KEY`. Нет — скажи, где взять ключ, и остановись.
- `HUNTER_API_KEY` желателен, но не обязателен: без него работает всё, кроме
  второго источника email.

## Что сделать

- `leadgen/providers/tavily.py` — реальный поиск за интерфейсом `SearchProvider`.
- `leadgen/providers/http_fetcher.py` — `httpx` + `trafilatura`. Загружает главную,
  about, услуги и контакты (не больше `MAX_PAGES_PER_SITE`). Проверяет `robots.txt`
  и ставит честный User-Agent, задаёт таймауты, обрезает текст страницы
  до `MAX_CHARS_PER_PAGE`. Если сайт запрещает обход, вернуть пустой результат
  (узел поставит `NO_DATA`).
- `leadgen/storage/cache.py` — SQLite-таблица `pages (url, text, fetched_at)` в `DB_PATH`.
  Фетчер сначала смотрит в кэш.
- `leadgen/providers/site_emails.py` — извлечение адресов из уже загруженных страниц:
  `mailto:`-ссылки и адреса в тексте контактной страницы. Классификация на `role`
  (`info@`, `sales@`, `hello@`, `contact@`, `office@`, `partners@`, `zakaz@`)
  и `personal` (всё остальное). Источник — URL страницы, где адрес найден.
- `leadgen/providers/hunter.py` — второй источник за интерфейсом `EmailFinder`.
  Используется, только если на сайте ничего не нашлось. Нет ключа — пустой результат.
- Правка узла `leadgen/graph/nodes/email.py`: каскад «сначала сайт, потом Hunter»,
  для каждого адреса сохраняются источник, тип и уверенность.
- Переключение реализаций по флагу `--offline` в `cli.py`: с флагом — фейки,
  без флага — реальные провайдеры. Сейчас без `--offline` CLI отказывается работать.
- Лог: сколько страниц загружено из сети, сколько взято из кэша.
- `.env.example` с именами переменных окружения. Загрузка `.env` при старте CLI.
- Новые зависимости — в `pyproject.toml`.

## Проверка кэша

Прогон на 3 доменах с замером времени, затем повторный: второй должен быть в разы
быстрее и не делать сетевых запросов к сайтам (видно по логу). Затем удалить
файл кэша и убедиться, что время вернулось к исходному.

## Приёмка

`leadgen run --limit 5`:
- получено 5 реальных доменов, это компании, а не каталоги и статьи;
- в логе видно, сколько страниц загружено;
- минимум у одной компании найден ролевой email с указанием страницы-источника.

Повторный запуск той же команды: ноль сетевых обращений к сайтам, видно в логе.
`leadgen run --offline --limit 3` и `pytest -q` по-прежнему проходят.

## Доводка после приёмки

- Мусорные домены из выдачи (каталоги, агрегаторы, статьи) — в `STOP_DOMAINS`.
- Сравнить объём текста с `/pricing` и `/cases` в наборе страниц и без них;
  оставить вариант, который даёт больше полезного текста.
