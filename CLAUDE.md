# Проект

Агент лидогенерации на LangGraph: по текстовому описанию идеального клиента (ICP)
находит компании, собирает факты с их сайтов, оценивает соответствие, находит email
и пишет черновик письма. Результат — CSV. Цель — рабочий инструмент по `SPEC.md`.

Владелец знает JavaScript и TypeScript, Python — слабо. Если он спрашивает про код,
объясняй через аналоги в TS/JS. Лекций без запроса не читай.

# Команды

- Прогон на фикстурах, без сети и без расхода лимитов: `leadgen run --offline --limit 3`
- Реальный прогон: `leadgen run --limit 5` — тратит лимит подписки Claude Pro
  (модель вызывается через `claude -p`, не через API), начинай с малого лимита
- Тесты: `pytest -q`
- Продолжить упавший прогон: `leadgen run --resume --thread-id <id>`

# Что где лежит

- `SPEC.md` — спецификация MVP. Читай нужные разделы перед работой над реализацией.
- `stages/stage-NN.md` — задания на оставшиеся этапы (4–8), по одному файлу на этап.
  Запуск этапа: `/stage N`.
- `PROGRESS.md` — что сделано, какие решения приняты, что осталось. Обновляй
  в конце каждого этапа.
- `evals/` — golden set, скрипт подсчёта метрик, журнал доводки промптов. Появляется
  на этапе 8.

Ни один из этих файлов не подключается автоматически: читай тот, который нужен задаче.

# Правила работы

- Этапы идут по порядку: каждый опирается на предыдущий. Одна новая внешняя
  зависимость за этап, чтобы при ошибке было понятно, кто виноват.
- `SPEC.md` меняй только с согласия владельца. Считаешь, что там ошибка, — скажи.
- Не утверждай ничего о файле, который не открыл, и не говори «работает», не запустив.
- Этап закрыт, только если команда приёмки из файла этапа запущена и вывод совпал
  с ожидаемым.
- Факты о компаниях живут только вместе с URL источника и дословной цитатой.
  Цитату проверяет код, а не просьба в промпте.
- Приоритет у ролевых email (`info@`, `sales@`). Персональные адреса — это персональные
  данные. Неподтверждённый адрес помечается `low_confidence` и не выдаётся за проверенный.
- Сайт, который запрещает обход в `robots.txt`, не трогаем: статус `NO_DATA`.

# Чего не делать

IMPORTANT: не добавляй абстракций, обработки невозможных ошибок и «улучшений» сверх задачи.
Не рефактори работающий код без спроса.

Временные скрипты и вспомогательные файлы удаляй в конце работы.
